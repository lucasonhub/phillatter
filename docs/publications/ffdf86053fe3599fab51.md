# Representation Drift in Continual Learning: LoRA versus N\-gram Memory

**Autores:** Hao Wu

**Data:** 2026-10-10 · **Tipo:** preprint

## Resumo

A language model that keeps learning online must not slowly erode its own base capabilities\. We ask which part of a modern LLM should absorb continual updates, by measuring how each choice changes the model&\#x27;s internal representations\. On a 48\-layer mixture\-of\-experts model with a native pretrained N\-gram memory, we train a seven\-task chain under three update mechanisms with identical data and budgets: updating only the N\-gram memory table, continually training one shared LoRA adapter, and training a fresh LoRA per task that is merged into the backbone\. We capture fixed\-context representations at every layer and task boundary\. Updating only the N\-gram memory changes the base model&\#x27;s representations of general math and code inputs by 26%/15% \(relative RMS\), against 64%/35% for merged and 97%/39% for shared LoRA\. This drift does not grow with the number of tasks: it reaches 25% after the first task and stays there for all seven, while both LoRA variants keep accumulating\. Its generic behaviour is essentially unchanged \(no code problem lost, math NLL \-0\.01\), and every change is confined to inspectable, reversible table rows\. The cost appears elsewhere: N\-gram memory acquires new tasks more weakly and its stored tasks interfere with one another, losing as much old\-task NLL as shared LoRA\. We show that this forgetting is governed by drift on the learned tasks&\#x27; own inputs, measured from the checkpoint at which each was learned, not by generic drift \(Spearman rho=0\.85; rho=0\.71 on Llama\-3\-8B\), and we derive the exact relations behind it: with a frozen head, every pairwise logit margin changes by the projection of drift onto a head\-difference direction\. These results support a design principle for long\-running online learning: write new knowledge only into the memory table and keep the backbone fixed; the remaining problem, interference between stored tasks, then lies inside the memory\.
