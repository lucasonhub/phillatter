# DB\-HSM: LLM\-driven semantic boundary debugging for network intrusion detection

**Autores:** Zeru Wang; Tadiwa Elisha Nyamasvisva

**Data:** 2026-10-14 · **Tipo:** article

## Resumo

Machine\-learning intrusion detectors reach high average accuracy yet fail consistently on a small set of flows near the decision boundary, where benign and attack traffic overlap in feature space\. These errors matter operationally, and standard remedies stop short: adversarial training adds perturbations whose gradients are weakly informative for tree ensembles; feature\-attribution methods rank which features matter but say nothing about what a feature value means; and oversampling interpolates in high\-dimensional feature space, breaking the correlations that make traffic features valid\. We reframe boundary\-error reduction as semantic debugging and propose DB\-HSM, in which a large language model \(LLM\) diagnoses why an already\-trained detector confuses a group of boundary flows and returns perturbation instructions rather than synthetic feature vectors\. Each instruction names 3\-5 features, a direction, and a magnitude in units of that feature&\#x27;s standard deviation; instructions are applied to real, correctly labelled boundary samples, so the enriched set inherits the natural joint distribution of traffic\. The loop runs for two rounds\. On UNSW\-NB15, DB\-HSM reduces total errors from 171 to 139 \(18\.7%\), improving F1 from 0\.9775 to 0\.9818; on CIC\-IDS2017 it reduces errors from 49 to 37 \(24\.5%\)\. Both single\-round and multi\-round gains hold across five seeds \(one\-sided Wilcoxon p = 0\.0312\)\. Direct measurement confirms three of the four LLM diagnoses and contradicts none\. A two\-round cycle costs roughly 96K tokens \(approximately $0\.03\)\. We report the absolute F1 gains as small and discuss when the method is, and is not, worth deploying\.
