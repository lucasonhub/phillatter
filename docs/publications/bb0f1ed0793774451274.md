  ## Overview This archive accompanies the TMLR paper *Evaluating the Effect of Numerical
  Solvers on Learning in Neural ODEs*. It provides PyTorch experiment scripts and
  supporting documentation for investigating how fixed-step Runge–Kutta methods influence
  the coarse numerical maps learned by Neural ODE classifiers. The paper asks whether
  a Runge–Kutta method''s **external scalar stability polynomial** is sufficient to
  characterize solver-dependent learning. Two controlled comparisons address this
  question: varying the Gegenbauer parameter while holding formal order and computational
  conditions fixed, and comparing ESRKG-15 with LSRKG-15, which have numerically matched
  external scalar stability polynomials but different internal tableaux and higher-order
  nonlinear B-series coefficients. The results support the conclusion that external
  stability structure matters but **does not determine the complete nonlinear Runge–Kutta
  update**. Further experiments use frozen-weight solver replacement and common-reference
  numerical refinement. A checkpoint may classify well under its training-time coarse
  discretization yet perform very differently when its learned vector field is numerically
  resolved. For example, on the fixed 1,000-image CIFAR-10 refinement subset, the
  paper reports an ESRKG-15 checkpoint changing from **85.4% native accuracy to 12.1%
  resolved accuracy**. This is a representative checkpoint-level result, not an assertion
  that all trained models show the same change. The third-order augmented Neural ODE
  exposes velocity, acceleration and third-order forcing for descriptive numerical
  diagnostics. Those diagnostics are **not** proposed as intrinsic geometric invariants,
  exact spectral quantities or stability certificates. First-order Neural ODE controls
  are also included. ## Contents The original supplementary ZIP has the following

  and CIFAR-100: solver comparisons (Section 4.3) The four principal configurations

  Example CIFAR-10 runs: ```bash python "CIFAR 10/rkcifar10.py" --dataset cifar10
  --h 2.5 --steps 4 --skip_adversarial python "CIFAR 10/esrk15cifar10.py.txt" --dataset
  cifar10 --h 10 --steps 1 --skip_adversarial python "CIFAR 10/esrk21cifar10.py" --dataset
  cifar10 --h 10 --steps 1 --skip_adversarial python "CIFAR 10/lsrkcifar10.py" --dataset
  cifar10 --h 10 --steps 1 --skip_adversarial ``` The ESRKG-15 CIFAR-10 script has
  the literal filename `esrk15cifar10.py.txt`; Python can execute it directly as shown,
  or it can be renamed locally to `.py`. For CIFAR-100, use the corresponding filenames
  under `CIFAR100/` **and explicitly pass `--dataset cifar100`**. For example: ```bash
  python CIFAR100/esrk15cifar100.py --dataset cifar100 --h 10 --steps 1 --skip_adversarial
  ``` At `Delta T = 20`, set `--h 20 --steps 1` for ESRKG/LSRKG methods and `--h 5
  --steps 4` for RK4. At `Delta T = 30`, use `--h 30 --steps 1` or `--h 7.5 --steps
  4`, respectively. The paper reports three independent seeds per configuration; rerun
  with appropriately recorded seeds, software versions and hardware details when making
  a quantitative comparison. In the newer training scripts, `--attack_seed` also initializes
  the training RNG. Use `--save_checkpoint PATH` in the newer training scripts if
  a weight file is needed for subsequent analysis. ### 2. Tiny-ImageNet (Section 4.3)

  --data ./data python Gegenbauer/esrkv2.py --dataset cifar100 --data ./data python
  Gegenbauer/visual.py ``` The default run configuration in these scripts uses horizon
