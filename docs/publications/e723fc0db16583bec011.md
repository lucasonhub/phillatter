# Independent Data\-Integrity Verification for LLM\-Driven Functional Coverage Closure in Hardware Design

**Autores:** Venkata Krishna Kumar Vedantam

**Data:** 2026-10-15 · **Tipo:** preprint

## Resumo

LLM agents can write directed tests that close functional coverage, but coverage only shows that a state was reached, not that the data on the way there was correct\. This is a long\-known point in verification and we do not claim it as new\. We describe a small coverage\-closure agent that applies it to an LLM loop: coverage is read from the report that the simulation itself exports \(cocotb\-coverage YAML\) and never taken from the model&\#x27;s account, and data integrity is checked by scoreboards that are separate from the model\. On three architecturally distinct RTL designs \(an asynchronous FIFO, a UART transmitter and an AHB2APB bridge\) the agent raised coverage from 91\.7%, 88\.9% and 67\.4% to 100% within its 8\-iteration budget in every logged run, using one design\-agnostic agent\. A reactive scoreboard monitor attached to the FIFO&\#x27;s base testbench also found a clock\-domain\-crossing bug in the author&\#x27;s own stimulus code\. The monitor is not yet attached to the LLM\-generated tests, so their data integrity is not independently checked; one manual check on a single FIFO test is reported as preliminary\. We list the weaknesses of this evidence: three designs, no baseline, no ablation, and logged runs that come from several agent checkpoints\.
